# DemoPilot — 研究、设计与验收 brief

配合根目录 [AGENTS.md](../AGENTS.md) 使用。初次资料核对：2026-11-03。项目尚未实现，以下方向需要原型与对照验证。

## 要解决的任务与核心亮点

开发者需要为应用功能拍一段易懂的演示，并在版本更新后低成本重拍。建议优先验证“可复录的演示配方”：可读操作步骤、真实录制片段、字幕/强调和剪辑决定可以关联、编辑和重用。

首版范围：本地或明确授权的浏览器应用、显式操作步骤、少量模板、预览与导出。不要先做自动编剧、多模态代理或庞大的模板市场。

## 技术探索应回答什么

1. 以 Playwright 的语义定位、状态等待、录制及 trace 作基础候选。trace 用于定位失败，不直接等同于可发布成片。对照真实录制与重放录制各自的状态稳定性。
2. 用步骤 ID 关联录制时间、字幕、缩放焦点和剪辑区间；优先保存可编辑的中间表示，避免修改一次字幕就必须重跑网站。
3. 对照 FFmpeg 式媒体处理和 Remotion 等可编程合成方案；以成片质量、可重现性、导出耗时、分发体积与许可决定。Remotion 的商业使用条件要读官方条款，不能默认等同于 MIT。
4. 自然语言或视觉模型只在明确收益后引入，例如步骤草拟、焦点建议；模型结果须可编辑和验证，定位失败不得编造操作成功。
5. 网站的字体加载、异步数据、随机内容、网络延迟和浏览器版本都会影响复录；能固定的固定，不能固定的记录并正确报错。

下面是已核对的一手研究入口；设计借鉴尚需观看真实演示和拆解截图。不会因列入表格就自动成为依赖或竞品超越结论。

| 参考 | 类型与用途 | 建议借鉴及边界 |
| --- | --- | --- |
| [Playwright Trace Viewer](https://playwright.dev/docs/trace-viewer) | 官方流程与调试文档 | 研究步骤、截图和执行证据的关联；保留故障定位能力，但不把调试 UI 当成片设计。 |
| [Remotion 文档](https://www.remotion.dev/docs/)及[许可入口](https://www.remotion.dev/docs/license) | 可编程视频合成与使用条件 | 评估参数化剪辑和预览一致性；许可、遥测和运行成本分别核实。 |
| [Screen Studio](https://screen.studio/) | 屏幕录制产品及官方演示 | 拆解焦点、缩放、节奏和画面留白；不能复制品牌资产，也不能仅凭官网认定其所有功能表现。 |
| [PR Preview](https://github.com/QwertyBit-Ventures/pr-preview) | PR 前后对比录像的直接替代方案 | 对照已有能力；本项目要用发布演示的编辑和复录体验证明自己的价值。 |

## 产品、内容与视觉方向

- 首页以“选择流程/录制/预览”为核心；主工作区是步骤大纲＋画面＋必要时间轴，避免先堆一屏模板和统计。
- 对比“大纲驱动”和“时间轴驱动”两种方案，选择让非视频编辑用户更容易修订演示的方向。
- 风格重点放在可读画面、准确停顿和操作焦点。只在信息需要时缩放或转场；不能每次点击都弹跳、摇镜、加音效。
- 字幕用真实动作与结果，不自动生成夸张营销话术；小尺寸 README 中仍看得清核心操作。
- 将录制源、剪辑预览、最终导出清楚区分。错误步骤和重试状态要可见；剪掉等待时保留说明，不能把剪辑后时长当系统实际响应时间。
- 样例只用合成数据与隔离登录态；录制前可预览遮挡范围，导出后检查秘密、个人信息及临时窗口是否泄露。

## 首版验收与演示

| 检查 | 最小证据 |
| --- | --- |
| 复录 | 同一示例流程至少连续跑 3 次，记录成功、失败与重试；这是稳定性冒烟检查，不是生产可靠性证明。 |
| 状态等待 | 正常、慢响应、定位目标缺失三类场景；不能靠不断加固定 sleep 隐藏问题。 |
| 可编辑性 | 修改一处字幕或强调范围后预览/导出正确；重录时步骤关联不丢失，失配会显式报告。 |
| 时间与成片 | 实际打开导出文件，核对字幕时序、帧率、时长、音画同步、缩放边界和小尺寸可读性。 |
| 异常 | 取消录制/导出、浏览器关闭、步骤失败或磁盘不足不产生“成功”假文件；临时数据可清理。 |
| 成本 | 记录端到端耗时、输出大小与人工编辑步骤，和手动录屏制作同一演示比较。 |

发布展示一条约 20–40 秒的真实功能流程，再改一个应用细节重新录制，证明“更新演示”的价值。配方中不得包含真实密码、会话 cookie 或生产数据。
